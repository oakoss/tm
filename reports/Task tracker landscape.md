# No tracker yet serves agents and humans

As of October 2026, no existing task tracker satisfies more than about three of the eight requirements set for an agent-and-human tracker. The landscape splits along one fault line. **Human-first tools** (Jira, Linear, GitHub Issues/Projects, Plane, Gitea/Forgejo, YouTrack, OpenProject) have strong UIs, PR automation and, in Linear's case, real release tracking. They are also server-authoritative: agents reach them only over metered APIs or MCP servers, with per-hour write budgets, and there is no local, lock-free read path. **Agent-first and git-native tools** (beads, Backlog.md, Taskmaster, Trekker, ticket, git-bug, TaskChampion, Radicle) keep data local and expose `--json` CLIs. They fail in other ways. Beads cannot be read from a read-only sandbox and shipped about seven weeks of default auto-push to the code remote. Backlog.md mints duplicate sequential IDs across clones and cannot see claims made in other worktrees. Taskmaster's single JSON file drifts in schema on every write. Four of the eight requirements go essentially unmet by every tool: review findings tracked against code, evidence on claims with runnable done-checks, file-path awareness beyond a free-form list, and release-bump awareness outside Linear's paid tier. The design implication is a hybrid. Item content should live as human-readable Markdown that travels with branches and PRs. Identity, claims and status should live in an append-only, ref-based operation log that every worktree can read without a lock and that is never published unless someone pushes it explicitly. On top of that sit typed validation, gates and a triage inbox that none of the local tools has yet assembled.

## Human-first trackers automate PRs well but keep agents at arm's length

The commercial majors have converged on treating agents as assignees, and each does it through a cloud-executed, metered product. Linear's model is the most careful. Assigning an issue to an agent app sets a separate `delegate` field so a human stays the accountable `assignee`. A mention or delegation opens an AgentSession, and the agent must emit a `thought` activity within **10 seconds** ([Linear developers: Agents](https://linear.app/developers/agents)). Jira puts Rovo and third-party agents in the assignee picker, on workflow transitions and on board columns, and each use **consumes Rovo credits**, with allowances starting 2026-12-03 ([Atlassian](https://support.atlassian.com/jira-software-cloud/docs/collaborate-on-work-items-with-ai-agents/)). Sources conflict on whether Jira's agents are GA or beta: search summaries said GA at Team '26, while the fetched help page states no beta status ([Techzine](https://www.techzine.eu/news/devops/139112/atlassian-gives-jira-and-rovo-agents-an-agentic-upgrade/)). GitHub's Copilot cloud agent is assigned like a user, works one repo, one branch and one PR per task, and has a **hard 59-minute cap** ([GitHub Docs](https://docs.github.com/en/copilot/concepts/agents/coding-agent/about-coding-agent)).

A local coding agent such as Claude Code gets none of that machinery. It gets the generic API or MCP path and its budgets. A Linear API key allows **2,500 requests per hour**, roughly 0.7 per second ([Linear rate limiting](https://linear.app/developers/rate-limiting)). GitHub caps content creation at **80 requests per minute and 500 per hour** ([GitHub REST rate limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)). Atlassian began enforcing points-based hourly quotas on 2026-03-02 ([Jira rate limiting](https://developer.atlassian.com/cloud/jira/platform/rate-limiting)). MCP tool schemas add context overhead on top. One practitioner measured Linear's MCP at more than 12,800 tokens for 42 tool definitions, and the same post reports MCP calls about 3x slower than a CLI on Jira; both figures are practitioner claims ([Quandri](https://quandri.io/engineering-blog/mcp-is-dead)). Linear Free's **250-issue cap** is the tightest economic constraint for an agent that files many small tasks ([Linear pricing](https://linear.app/pricing)).

Where the majors excel is linking code to work items. Linear has the richest PR automation. It recognizes closing words (fixes, closes, resolves) and non-closing words (refs, part of, contributes to). An issue moves only when the **last** of its linked PRs reaches a state, rules match target-branch regexes, and "ready for merge" fires only when GitHub reports a stable, mergeable PR, so a failing check blocks it ([Linear GitHub docs](https://linear.app/docs/github)). GitHub closes issues natively, but **only for PRs targeting the default branch**, which breaks release-branch workflows ([GitHub Docs](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/linking-a-pull-request-to-an-issue)). Jira's Smart Commits require the committer email to match a Jira user, which is a problem for agent commits made under bot identities ([Atlassian](https://support.atlassian.com/jira-software-cloud/docs/process-issues-with-smart-commits/)). Linear Releases (Business+) is the only release-aware system in the whole landscape. On each deploy, a CLI or GitHub Action scans new commits for IDs like ENG-123, attaches those issues to a release in a pipeline, and can scope the pipeline to path globs such as `mobile-ios/**` ([Linear Releases](https://linear.app/docs/releases)).

Typed fields arrived late on GitHub. Org-level issue fields (single select, text, number, date) went GA on **2026-07-02**, capped at **25 per org** and pinnable to issue types ([GitHub changelog](https://github.blog/changelog/2026-07-02-issue-fields-are-now-generally-available/)). Whether they can be marked required on creation is unverified. Linear's main enforcement knob is requiring priority before an issue leaves Triage ([Linear Triage](https://linear.app/docs/triage)). Jira's validator, condition and required-field engine, the richest of the group by reputation, was not fetched from primary docs and is labeled unverified in the notes.

Among self-hostable tools, Plane (AGPL-3.0, 60,955 stars) is the closest open-source Linear equivalent. It needs **4–8 GB of RAM** under Docker Compose ([Plane self-hosting](https://developers.plane.so/self-hosting/methods/docker-compose)). Its GitHub integration is a Pro feature with a borrowable convention: a bracketed `[WEB-344]` triggers state automation while a bare `WEB-345` only links ([Plane GitHub docs](https://docs.plane.so/integrations/github)). Its Intake guarantees that items "always start in Triage" regardless of source ([Plane changelog](https://plane.so/changelog/2025-12-23-intake-ownership-ai-context-editor-work)). YouTrack Server's built-in MCP exposes a "get field schema" tool, `enableToolOutputSchema=true` and admin controls that hide projects from AI tools ([YouTrack MCP docs](https://www.jetbrains.com/help/youtrack/server/model-context-protocol-server.html)). That is the clearest example of giving agents the schema they need to satisfy typed fields. OpenProject's MCP is experimental, read-only and Enterprise-gated ([OpenProject docs](https://www.openproject.org/docs/system-admin-guide/integrations/mcp-server)). Gitea ships an official `gitea-mcp` with issues, PRs and milestones ([gitea-mcp](https://gitea.com/gitea/gitea-mcp)) and configurable close/reopen keywords ([Gitea source](https://github.com/go-gitea/gitea/blob/main/modules/references/references.go)).

Two cautionary closures sharpen the case for exportable data. Huly's hosted service was discontinued and its upstream repo is now frozen ([hcengineering/platform](https://github.com/hcengineering/platform)). Height shut down in 2025 ([AlternativeTo](https://alternativeto.net/news/2025/3/height-project-management-tool-to-shut-down-by-september-2025/)). Jira Data Center reaches end of life on **2029-03-28**, per consistent secondary sources ([getint](https://www.getint.io/blog/jira-data-center-end-of-life)), which leaves GitHub Enterprise Server as the only self-hosting path among the commercial majors.

## Agent-first trackers trade coordination safety for local speed

Beads is the most feature-complete agent tracker and the one with the most operational problems. It has **27,941 stars**, its npm package logged 34,233 downloads in the month to 2026-10-12, and its repo has been transferred to `gastownhall/beads` ([repo](https://github.com/gastownhall/beads)). Its agent ergonomics are the strongest in the category. It offers hash IDs that adapt in length to database size ([adaptive-ids.md](https://github.com/gastownhall/beads/blob/main/docs/core-concepts/adaptive-ids.md)), atomic claims where "the first claim wins" ([coordination.md](https://github.com/gastownhall/beads/blob/main/docs/multi-agent/coordination.md)), a `bd ready` queue over typed dependency edges, and semantic compaction. It also has **gates** that block dependents on `gh:pr` merged, `gh:run` CI success, timers or a human. The stated reason for gates is that "issue state is decoupled from code state", so closing a bead does not mean the code is on main ([dependencies.md](https://github.com/gastownhall/beads/blob/main/docs/core-concepts/dependencies.md)). Since March 2026 Dolt is the only backend ([CHANGELOG](https://github.com/gastownhall/beads/blob/main/CHANGELOG.md)). Sources disagree on when embedded mode became the default: the CHANGELOG lists it under v1.0.0, while the DoltHub post shows it at v0.63.3 ([DoltHub](https://www.dolthub.com/blog/2026-04-02-restoring-beads-classic/)). Embedded mode is **single-writer behind a file lock** ([dolt.md](https://github.com/gastownhall/beads/blob/main/docs/architecture/dolt.md)). It also **cannot be opened even for a pure read inside a sandbox that denies writes**, because the Dolt chunk journal is opened read-write; this reproduces under Codex CLI's read-only sandbox ([#7445](https://github.com/gastownhall/beads/issues/7445)).

Beads' sync model is the clearest privacy lesson in the landscape. `bd init` auto-wires the code repo's `origin` as a Dolt remote and publishes `refs/dolt/data` there ([sync-concepts.md](https://github.com/gastownhall/beads/blob/main/docs/core-concepts/sync-concepts.md)). Auto-push with a 5-minute debounce shipped in v0.57.0 (2026-03-01) and was made opt-in only by PR #3446, which merged on 2026-04-24 and shipped in v1.0.3 ([PR #3446](https://github.com/gastownhall/beads/pull/3446)). Open issues show that stealth mode still attempts pushes ([#3463](https://github.com/gastownhall/beads/issues/3463)), that a failed push still advances `last_push` so `bd doctor` reports green ([#6289](https://github.com/gastownhall/beads/issues/6289)), that a hung push holds the lock and blocks every other `bd` process ([#3370](https://github.com/gastownhall/beads/issues/3370)), and that `git push --mirror` destroys the data ref ([#5266](https://github.com/gastownhall/beads/issues/5266)). Beads also sprawls on the human side. It has **70+ commands**, which is why `bd human` exists to print about 15 essential ones and to serve as an inbox for human-needed items ([human.md](https://github.com/gastownhall/beads/blob/main/docs/cli-reference/human.md)). Its human UI is outsourced to roughly 30 community TUIs, web UIs and editor plugins of varying freshness ([community-tools.md](https://github.com/gastownhall/beads/blob/main/docs/community-tools.md)). Validation is advisory: `bd lint` flags missing Acceptance Criteria sections but does not block ([lint.md](https://github.com/gastownhall/beads/blob/main/docs/cli-reference/lint.md)). Commit linkage is report-then-confirm through `bd orphans`, not automatic closing ([orphans.md](https://github.com/gastownhall/beads/blob/main/docs/cli-reference/orphans.md)). No release field or core file-path field was found.

Beads' complexity has spawned a family of reactions. Each one gives up something beads offers in exchange for a property beads lacks. beads_rust freezes the classic SQLite + JSONL design and "never commits, pushes, pulls, installs hooks, or runs as a background service" ([beads_rust](https://github.com/Dicklesworthstone/beads_rust)). ticket (`tk`) is a single bash script that stores Markdown files with YAML frontmatter in `.tickets/` under prefix-plus-hex IDs like `nw-5c46`, which double as clickable filenames ([ticket](https://github.com/wedow/ticket)). Trekker is a Bun + SQLite CLI with FTS5 search, an audit history and a kanban dashboard. Its author built it after concerns about beads' "future and security". It has no sync model, uses sequential IDs in a gitignored database, has 154 monthly npm downloads, and has seen no push since April 2026 ([Trekker](https://github.com/obsfx/trekker)).

Backlog.md is the strongest file-based tool for humans and the most honest about its coordination limits. It is TypeScript and MIT-licensed, at v1.54.0 on 2026-10-16, with **87,203 monthly npm downloads** ([repo](https://github.com/MrLesk/Backlog.md)). Each task is a Markdown file whose frontmatter includes `modified_files[]` and `references[]`, which makes it the only tool found with a per-item file-path field. Machine-delimited body sections round-trip acceptance criteria, Definition of Done and an implementation plan ([BACK-769](https://github.com/MrLesk/Backlog.md/blob/main/backlog/tasks/back-769%20-%20Keep-generated-task-comments-as-plain-Markdown-text.md)). It ships a terminal board, a local web Kanban bound to 127.0.0.1, stable versioned JSON with a `--watch` stream, and an MCP server. Its `init` now recommends **CLI instructions over MCP** by default ([README](https://github.com/MrLesk/Backlog.md)). Its weak point is identity and ownership. Sequential `max + 1` IDs "deterministically mint the same ID" across clones, and the maintainer shipped detection and repair rather than prevention ([#711](https://github.com/MrLesk/Backlog.md/issues/711)). A status or assignee change in one worktree "is invisible everywhere else until that branch is merged", so two agents can take the same task ([BACK-760](https://github.com/MrLesk/Backlog.md/blob/main/backlog/tasks/back-760%20-%20Share-task-IDs-assignment-and-status-across-branches-and-worktrees.md)). Cross-branch scanning once caused minutes-long hangs, until v1.50.1 made CLI reads local-only and cut warm reads from about 394 git operations to 3 or fewer ([v1.50.1](https://github.com/MrLesk/Backlog.md/releases/tag/v1.50.1)).

Taskmaster is a planner more than a system of record. It decomposes PRDs into tasks with LLM calls, is MCP-first with **36 tools costing about 21,000 tokens** by default, and stores everything in one `tasks.json` ([README](https://github.com/eyaltoledano/claude-task-master)). That file drifts in schema on every `set-status` call ([#1708](https://github.com/eyaltoledano/claude-task-master/issues/1708)), and a stale MCP tag state corrupts data across tags ([#1637](https://github.com/eyaltoledano/claude-task-master/issues/1637)). The repo has been idle since April 2026 while team features moved to the commercial Hamster cloud ([Hamster docs](https://tryhamster.com/docs/taskmaster/team/overview)). Built-in agent task lists are retreating. Claude Code's Task tools are default-off on models newer than Opus 4.7 and Sonnet 4.6 as of v2.1.268, and they persist under `~/.claude/tasks/`, outside the repo ([Claude Code tools reference](https://code.claude.com/docs/en/tools-reference)). Codex made `update_plan` opt-in on 2026-08-31 ([PR #41744](https://github.com/openai/codex/pull/41744)). One secondary source attributes the change to models splitting progress between the built-in plan and external trackers ([Vaughan](https://codex.danielvaughan.com/2026/08/31/codex-cli-update-plan-tool-opt-in-external-planning-competing-surfaces/)). Together these moves leave room for a durable tracker that agents reach through a CLI.

The older git-native tools solved the coordination problems that Backlog.md now faces. git-bug stores each entity as a chain of operation-pack commits under `refs/bugs/*`. It orders operations by Lamport clock and breaks ties deterministically by OperationPack ID, so concurrent edits merge without conflicts ([data-model.md](https://github.com/git-bug/git-bug/blob/master/doc/design/data-model.md)). Data leaves the machine only on an explicit `git bug push` ([git-bug push](https://github.com/git-bug/git-bug/blob/master/doc/md/git-bug_push.md)). It has bridges to GitHub, GitLab, Jira and Launchpad, but no label validation, no PR entity and only partial boards ([feature-matrix.md](https://github.com/git-bug/git-bug/blob/master/doc/feature-matrix.md)). Radicle COBs union commit DAGs "in a non-destructive, idempotent way", and patches share the same storage model as issues. Private repos replicate only to trusted peers but are "not encrypted at rest" ([Radicle protocol guide](https://radicle.dev/guides/protocol)). TaskChampion syncs operations through a server that "does not have access to the task data", using **ChaCha20-Poly1305** with a PBKDF2 key, and stores tags and dependencies under separate keys so independent edits commute ([sync model](https://gothenburgbitfactory.org/taskchampion/sync-model.html); [encryption](https://gothenburgbitfactory.org/taskchampion/encryption.html); [task model](https://gothenburgbitfactory.org/taskchampion/tasks.html)).

Three readings stand out. First, only Linear clears the PR and release columns, and it does so behind Business-tier pricing and a cloud API that agents reach at 0.7 requests per second. Second, the private-sync column is where the agent-first leader fails hardest. Beads publishes to the code remote, has reported green after failed pushes, and cannot open its store from a read-only sandbox ([#7445](https://github.com/gastownhall/beads/issues/7445)). git-bug and TaskChampion pass this column but offer almost nothing else in the matrix. Third, the two columns closest to the user's workflow (review findings tied to code, and runnable done-checks with evidence) are empty. The nearest mechanisms all stop short. Linear's mergeable gate treats green CI as the proxy for done. Backlog.md's acceptance-criteria checkboxes are ticked by hand. Beads' `gh:run` gate waits on CI but records no evidence. None of them lets an item declare "run this command, expect this result" and store the run's output as proof, and none models a review finding as an item anchored to a file and line with its own resolution state.

## Proven mechanisms worth borrowing, and where each comes from

The strongest borrowable idea is splitting content from coordination. BACK-760's measurements explain why. Shared values written into task files on two branches conflict "also when the two branches changed different adjacent frontmatter lines". In contrast, "`git update-ref` with an expected old value lets exactly one of 20 parallel writers win" ([BACK-760](https://github.com/MrLesk/Backlog.md/blob/main/backlog/tasks/back-760%20-%20Share-task-IDs-assignment-and-status-across-branches-and-worktrees.md)). The same task records three traps a design must handle. Byte-identical pushes both report success, so every write needs a unique component. A wildcard fetch with `--prune` deletes local copies of custom refs. Treating "already has the requested value" as success produced **40 winners for 8 tasks**, so a take must succeed only on an unassigned item. A community fork already applies this with "one atomic conditional write to `refs/claims/<ticket>`" that leaves the task file untouched ([#1063](https://github.com/MrLesk/Backlog.md/issues/1063)). For the coordination layer itself, git-bug's operation packs supply the mechanics: hash-of-first-op IDs, Lamport clocks stored in tree entry names, and DAG-respecting clock validation as an anti-abuse check ([git-bug data-model](https://github.com/git-bug/git-bug/blob/master/doc/design/data-model.md)). Two further patterns make concurrent edits commute instead of conflicting. TaskChampion stores each tag and dependency under its own key ([TaskChampion](https://gothenburgbitfactory.org/taskchampion/tasks.html)), and git-appraise writes one JSON line per item, merged with `cat_sort_uniq` ([git-appraise](https://github.com/google/git-appraise)). Fossil shows that query tables can always be rebuilt from the append-only change log ([Fossil](https://fossil-scm.org/home/doc/trunk/www/tickets.wiki)). That property makes a fast index a disposable cache rather than a second source of truth, which avoids the dual-storage drift that `tk`'s author blamed on beads.

IDs need to serve humans and agents at once. Backlog.md users rejected 8-hex IDs as inconvenient to type ([#711](https://github.com/MrLesk/Backlog.md/issues/711)). Taskwarrior's renumbering working-set IDs are a known hazard for agents (aggregator claim; [mcp.so listing](https://mcp.so/servers/awwaiid_mcp-server-taskwarrior)). Beads' adaptive-length hash IDs ([adaptive-ids.md](https://github.com/gastownhall/beads/blob/main/docs/core-concepts/adaptive-ids.md)) and `tk`'s prefix-hex filenames ([ticket](https://github.com/wedow/ticket)) are the working compromises. A sequential alias allocated through ref CAS is the untested alternative the notes propose. Backlog.md's rule that ambiguous IDs "fail closed everywhere" ([releases](https://github.com/MrLesk/Backlog.md/releases)) belongs in any design.

For code and release linkage, five mechanisms are worth copying. From Linear: closing versus non-closing verbs, aggregation over all linked PRs, a stable-mergeable gate ([Linear GitHub](https://linear.app/docs/github)), and release membership derived from commit-ID scans plus path globs ([Linear Releases](https://linear.app/docs/releases)). From Plane: the bracketed-versus-bare reference rule, which prevents accidental closes from incidental mentions ([Plane GitHub](https://docs.plane.so/integrations/github)). From beads: gates, which stop "closed" from meaning "merged" ([beads dependencies](https://github.com/gastownhall/beads/blob/main/docs/core-concepts/dependencies.md)). From git-bug's bridge bugs: external IDs should be stored as first-class metadata, because GitHub round trips once duplicated every comment ([v0.11.0](https://github.com/git-bug/git-bug/releases/tag/v0.11.0)).

For the agent surface, four precedents apply. A self-documenting CLI with stable, versioned JSON comes first, with MCP as an option. Backlog.md now defaults to CLI instructions ([README](https://github.com/MrLesk/Backlog.md)), and beads' docs estimate 1–2k tokens for CLI plus hooks against 10–50k for MCP ([mcp-server.md](https://github.com/gastownhall/beads/blob/main/docs/integrations/mcp-server.md)). Agents should get the field schema as data, following YouTrack ([YouTrack MCP](https://www.jetbrains.com/help/youtrack/server/model-context-protocol-server.html)). Delegation should keep a human accountable while an agent executes, as Linear's delegate field does, with streamed activities ([Linear agents](https://linear.app/developers/agents)). Finally, there should be a small human command set, which beads had to retrofit as `bd human`. For triage, Plane's "intake always starts in Triage" ([Plane](https://plane.so/changelog/2025-12-23-intake-ownership-ai-context-editor-work)) and Linear's exclusion of triage items from default views plus a required field to leave triage ([Linear Triage](https://linear.app/docs/triage)) set a clean invariant: agent-filed items land unaccepted until a human or a completeness rule promotes them.

## Conclusion

The landscape has not converged because each camp optimizes the wrong source of truth for the other's needs. Human tools centralize truth on a server, which buys PR automation, release tracking and triage but taxes every agent read. Agent tools put truth in a local database (beads, Trekker, Taskmaster) or in working-tree files (Backlog.md, `tk`). The first fails read-only and privacy tests, and the second fails identity and claim tests. Backlog.md's own roadmap, moving IDs and assignment into refs while keeping Markdown bodies, is the clearest sign of where a correct design sits. Its maintainer has scoped it narrowly, without leases for crashed agents, and that question remains open.

A new tracker's differentiation would come from the gaps no tool fills, not from reassembling known patterns. First, done-checks should be stored commands whose execution output becomes attached evidence, so "closed" carries proof rather than a ticked box. Second, review findings should be first-class items anchored to file, line and commit, with their own resolution state and linked to the parent item. Third, file paths on items should be structured, so an agent can ask which open items touch a given file. Fourth, release membership should be derived locally from tags and version bumps rather than from a paid cloud pipeline. Fifth, no tool combines lock-free read-only access from a sandbox with sync that publishes nothing unless explicitly pushed and that verifies push state against the remote instead of trusting local bookkeeping. Each of these is cheap to state and absent from every tool surveyed. The unverified cells in the matrix (Jira validators, GitHub required fields and triage, Plane releases) are the places to confirm before treating the incumbents' gaps as settled.
